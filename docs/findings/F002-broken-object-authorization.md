# F002 — Unscoped conversation access and cross-tenant retrieval

1. **Name:** Broken object-level authorization in local repository composition.
2. **Component/entry point:** `ConversationRepository.read/append` and `DocumentRepository.retrieve`; reproduced by `npm run lab:bola`. No vulnerable HTTP route exists. The hardened API uses these repositories through default constructors.
3. **Preconditions:** local synthetic lab, known foreign conversation UUID (printed by fixture setup), valid Northstar actor, and explicit `LAB_OBJECT_MODE=vulnerable` at CLI startup. No external discovery or identifier enumeration is demonstrated.
4. **Root cause:** conversation lookup treats existence as permission, omitting tenant and owner predicates; retrieval omits tenant filtering before ranking. These are two related enforcement sites, both retained in one scoped finding record rather than inflated into multiple findings.
5. **Trust boundary:** an authenticated caller's chosen object ID/query crosses into data belonging to another user or tenant. Authentication does not establish object permission. A UUID is not an access control.
6. **Discovery method:** deterministic multi-identity repository tests and an isolated local CLI replay, plus inspection of actual adapter context for a foreign canary.
7. **Reproduction:** run `npm run lab:bola` (hardened, exit 0) and `LAB_OBJECT_MODE=vulnerable npm run lab:bola` (expected exit 1). Each process creates disposable Harbor conversation state and attempts Northstar reads/writes plus subscription retrieval. Restarting resets everything.
8. **Requests/results:** the CLI requests `read(northActor, harborConversationId)`, `append(northActor, harborConversationId, {content: "unauthorized-modification"})`, and `retrieve(northActor, "subscription")`. Hardened read/write throw generic `Resource not found`, preserve one original message, and return only Northstar sources. Vulnerable results include the Harbor private message, a second unauthorized message, and `harbor-guide`. Captured outputs are linked from Phase 6 evidence. These are actual local function results, not fabricated HTTP responses. Existing HTTP negative tests verify hardened 404 semantics.
9. **Business impact:** modeled disclosure and tampering of another customer's private support history and cross-tenant information entering model context. The scripted model does not echo raw retrieval data, so client-visible model exfiltration is not claimed. All actual data is synthetic.
10. **Severity:** high modeled confidentiality/integrity impact if deployed with real tenant data. Actual lab exposure is local synthetic state with no vulnerable listener. No CVSS score is assigned without deployment assumptions.
11. **Remediation:** enforce actor tenant AND conversation owner at each repository read/write; derive ownership from authenticated actor on creation; filter retrieval tenant/classification before scoring. Manager role grants no ownership override. Default constructors remain hardened. Do not rely on prompt rules, UUID secrecy, or post-response filtering.
12. **Regression:** `tests/bola.test.ts` checks all 25 caller/owner pairs under both compositions, applies identical denial/context-isolation invariants with expected vulnerable failures, verifies denied writes preserve state, and varies tenant independently while owner ID stays constant. Existing HTTP and repository tests remain enabled.
13. **Mappings:** [OWASP API1:2023](https://api-security.owasp.org/editions/2023/en/0xa1-broken-object-level-authorization/) directly applies to missing object scope. [ASVS 5.0 V8.3.1](https://github.com/OWASP/ASVS/blob/master/5.0/docs_en/OWASP_Application_Security_Verification_Standard_5.0.0_en.csv) concerns enforcement at the trusted service layer. No prompt-injection, ATLAS model-attack, or agentic mapping is added: these failures require no model manipulation. Cross-tenant model context exposure is the AI-relevant consequence, not evidence of a new model vulnerability.
14. **Residual risk:** in-memory predicates are not database row-level security or distributed isolation. Unknown/missing-object 404 semantics do not guarantee timing equivalence. The retrieval bypass preserves classification and size limits. Customer-record tool access remains hardened and has no additional vulnerable reproduction in this phase. Actor authentication is trusted in-process; fixture tokens remain public synthetic identities.
